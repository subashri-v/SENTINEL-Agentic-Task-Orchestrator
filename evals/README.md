# Evaluation harness

Measures the orchestrator so any number you quote is reproducible. Run from the repo root.

```
python -m evals.run_eval --mode route --per-category 3   # cheap smoke test (orchestrator only, no DB)
python -m evals.run_eval --mode all                      # routing + full graph + retrieval
```

Per-case results (questions, answers, retries, grades) are written to `evals/results/` (gitignored).
**Read a sample of them by hand before trusting any number.**

## What it reports

| Section | Meaning |
|---|---|
| Routing accuracy | Orchestrator's chosen agent vs. the `category` label, overall and per agent, with 95% Wilson CIs and a list of misroutes. |
| Pipeline outcomes | Share of cases auto-resolved vs. escalated to a human, and the retry distribution (0/1/2). |
| Answer quality | First-pass correctness (what you would get with no evaluator) vs. final correctness after retries, plus how often the evaluator accepted good answers, rejected bad ones, and how many bad answers a retry fixed. |
| Latency | End-to-end p50/p95, overall and per route. |
| Retrieval | hit@k and MRR over `retrieval_cases.jsonl`. |

The full graph runs on an in-memory checkpointer, so `checkpoints.db` is untouched. It does call the live
services (NVIDIA, Gemini, Tavily, GitHub) and writes nothing to `hotl_audit_logs`.

## Case files

`cases.jsonl` is generated by `make_cases.py` (edit and rerun it). Fields:

- `category`: the expected route (`MATH`, `RAG`, `GITHUB`, `TAVILY`, `SUMMARY_AGENT`)
- `history`: optional prior `[role, text]` turns seeded into the thread (needed for summary and follow-up cases)
- `expect_all`: substrings that must all appear in the answer (whitespace/case-insensitive). Used for MATH.
- `reference`: reference answer, graded by an LLM. Used for SUMMARY_AGENT.
- neither: the case is route-only, so correctness is not graded (live web/GitHub data changes too fast).

**The starter set is mine, not yours. Review the labels.** RAG questions are generic and should be rewritten for
whatever you have ingested. Only MATH and SUMMARY_AGENT answers are graded.

`retrieval_cases.jsonl` ships empty. Add lines like
`{"question": "...", "expected_source": "handbook.pdf", "expected_text": "March 15"}` for documents you ingested.

## Caveats to keep in mind (and to be honest about in an interview)

- The in-loop evaluator and the answer grader are both Gemini by default. `--grader-model` lets you use a
  different one. MATH grading is programmatic and has no such overlap.
- Small samples mean wide intervals. Report the CI or the raw `k/n`, and use `--repeats` to average out LLM noise.
- "First-pass correct" comes from the same run as "final correct", so the difference between them is the
  evaluator and retry loop's contribution without a separate ablation run.
- An escalated case counts as a rejection at the evaluator level. A Gemini error also escalates, so a flaky
  evaluator can inflate the escalation rate.
- `--generator-model` overrides `config.NVIDIA_MODEL` for one run, so you can compare models without editing config.
